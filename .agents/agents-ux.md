# UX Domain Module

> Loaded by Task Router for UI/UX operations.

## Visual Proof-of-Work Policy

All frontend/UI changes MUST include:
1. **Clickable mockup** (HTML/React) generated by the Builder
2. **Screenshot evidence** captured via browser-provider
3. **Before/After comparison** attached to PR description

## Browser Provider Setup

```yaml
provider: playwright
headless: true
viewport: { width: 1280, height: 720 }
screenshot_format: png
output_dir: .agents/screenshots/
```

## UX Review Workflow

```
Design Spec → om-ux-shape → Implementation → om-ux-review-pr → Screenshot → QA Gate
```

### Phase 1: Shape (Design)
- **Skill**: `om-ux-shape`
- **Input**: User story or design brief
- **Output**: Component specification with acceptance criteria

### Phase 2: Setup (Scaffold)
- **Skill**: `om-ux-setup`
- **Input**: Component spec from Phase 1
- **Output**: Scaffolded component with design tokens

### Phase 3: Review (QA)
- **Skill**: `om-ux-review-pr`
- **Input**: PR with UI changes
- **Output**: Visual diff report + accessibility audit

## Design Principles
1. **Mobile-first**: All layouts responsive by default
2. **Accessible**: WCAG 2.2 AA minimum
3. **Consistent**: Use design tokens, not magic numbers
4. **Documented**: Every component has a visual example
